# Skill: Layout Safety

## 目标

避免“动画本身没出屏，但和字幕/标题/平台 UI 互相遮挡”的结构性错误，也避免连接线、镜头残留、时间轴漂移造成的视觉错误。这个 skill 处理的是**整个视频的空间与时间契约**，不是某个元素的临时坐标修补。

## 1. 先定画幅，再写动画

在任何 scene 开发前明确：

- 正文画布尺寸。
- 输出帧率。
- 顶部标题区（如果这一期确实需要）。
- 主视觉区。
- 字幕保留区。
- 平台 UI 需要避让的区域。

`project.meta`、capture viewport、最终 FFmpeg 输出必须使用同一画幅。任何一处不一致都应直接失败。

## 2. 内容区和字幕区必须物理分离

字幕不是“最后盖上去的一层文字”，而是从一开始就占据画布空间。

默认规则：

- Motion Canvas 的主内容不得进入字幕保留区。
- 字幕烧录只能进入自己的保留区。
- 不能只检测“字幕有没有出屏”；还必须判断“字幕有没有遮住正文”。
- 画面里的说明文字不能只是当前字幕的重复版本；说明文字只承担关系、状态、实体、决策等视觉信息。

### 16:9 / 1920×1080 基准

当前 7BYTE 横版基准：

- 主要视觉带：约 `y=-360..300`。
- 字幕保留带：约 `y=320..500`。
- 正文实体、状态卡、说明条禁止进入字幕保留带。

这不是要求每期使用完全相同坐标，而是要求**视觉内容和字幕永不互相抢空间**。

## 3. 容器内部布局必须显式声明

EP003 暴露过一个普遍问题：`Rect` 有宽高和边框，不代表其子元素就会自动居中。若容器没有开启布局并声明对齐，文字、图标、嵌套 Layout 很容易落在局部坐标原点附近，视觉上表现为“所有文字挤在框的左上角”。

因此，任何承担 UI 容器职责的 `Rect / Layout` 都必须明确回答：**里面的东西如何排列、如何对齐？**

默认规则：

- 单内容居中卡：显式 `layout + alignItems={'center'} + justifyContent={'center'}`。
- 横向信息卡：显式 `layout + direction={'row'}`，并声明 `alignItems / justifyContent / gap / padding`。
- 纵向信息卡：显式 `layout + direction={'column'}`，并声明 `alignItems / justifyContent / gap / padding`。
- 只有确实需要自由坐标排版时，才允许关闭 layout；此时每个子元素都必须有有意的 `x/y`，不能依赖默认位置。
- 图标 + 标题 + 状态值的卡片，禁止只给外框尺寸然后让内部节点靠默认坐标“碰巧看起来对”。
- 重复生成的卡片/bit 单元必须使用同一套对齐契约，不能只修截图里某一个实例。

视觉审计新增硬门槛：随机抽查至少一个单内容卡、一个横向卡、一个纵向卡、一个重复单元，确认文字/图标在容器内的视觉中心和设计意图一致。

## 4. 信息结构决定方向

不要因为平台常见竖屏，就强行把所有内容做成纵向。

优先横版的情况：

- 因果链路 / 网络链路 / 数据流。
- 多节点对比。
- 时间轴。
- 左右输入输出关系。
- 需要同时看到多个实体之间关系。

优先竖版的情况：

- 单一主体。
- 从上到下自然递进。
- 手机 UI / 单列流程。

判断标准：**选择能让关系最清楚的画幅，而不是让内容勉强塞进预设模板。**

## 5. Connector 安全

流程图/网络图的线条属于结构信息，不能靠肉眼估坐标。

必须：

- 端点绑定到节点几何信号，例如 `node().right()` → `next().left()`。
- 节点移动或尺寸变化时，线条自动跟随。
- connector 与节点放在同一个 shot/group；group 初始 `opacity=0` 时 connector 也不可见。
- 禁止无 ref、无显隐状态管理的常驻辅助线。
- 禁止用两个分离的短横线“拼”一个断点；断点用明确的 `×`/状态 badge 表达。

发布前关键帧必须确认每一条线：**起点接边、终点接边、没有穿过卡片、没有悬空。**

## 6. 状态变化必须满足布局契约

初始帧不重叠，不代表动画过程安全。

每次执行以下操作后都要重新检查：

- `x / y` 位移。
- `scale`。
- 动态修改文本。
- 节点显隐。
- 卡片尺寸变化。
- 多实体同时出现。

特别注意：后绘制节点可能覆盖先绘制的标题或说明文字。不要依赖 z-order 去掩盖空间冲突。

对于结构变化较大的镜头，优先使用独立 shot 整体切换，不要让一组节点同时移动、缩放、改尺寸去承担另一套拓扑。

## 7. 字幕安全

字幕规则与 `auto-subtitles.md` 配合：

- 最多两行。
- 每行做真实像素宽度检测。
- 过长先按语义拆 cue，再换行。
- 技术 token 不拆开。
- 字幕位置必须固定在预留字幕带。
- 不允许为了塞下某一句临时缩小字号或降低安全边距。

## 8. 时间轴与结尾安全

注释里的 `30s / 40s` 不等于真实运行时间。多个 `yield*`、`sequence`、过渡动画会改变累计时长。

要求：

- TTS timing / narration cue 是正文时间的 source of truth。
- 每个 phase 使用明确的总时长；阶段内部动画必须包含在这个总时长里，不能“动画时长 + waitFor”不断累加造成漂移。
- 推荐做法：`all(waitFor(phaseDuration), ...phaseAnimations)`，让阶段总时长固定。
- 正文结束时间必须 >= 最后一条**正文解释**旁白结束时间；若最后一条是品牌口播，可把它归属 canonical outro，并让 body end 与该 cue start 精确绑定。
- capture 可以略长，但最终拼接正文必须 trim 到明确的正文终点。
- 最后 2 秒必须抽帧确认没有播放器 loop 回第 0 帧。
- canonical 片尾只能在明确 body end 开始；如果品牌口播属于片尾，音频 cue 与片尾第一帧必须同步，不允许“正文先说完口号，再切片尾”。

任何“结尾又出现开头画面”或“品牌口播与片尾错位”的情况都视为**阻断发布的时间轴错误**。

## 9. 渲染几何校验

capture 工具必须比较：

`请求宽高 == Motion Canvas canvas 实际宽高`

不一致直接报错。禁止浏览器 CSS 缩放、viewport 变化或旧默认值悄悄改变最终构图。

## 10. 发布前关键帧审计

每次最终渲染后至少抽查：

1. `0–1s`：初始化/Hook。
2. 每个 shot 切换前后各一帧。
3. 信息结构第一次完整展开。
4. 节点/连线最多的一帧。
5. 每一种故障状态。
6. 字幕最长的一句。
7. 正文最后 2 秒。
8. 片尾开始后 1 秒。
9. 至少四类容器内部对齐样本：单内容、横向、纵向、重复单元。

检查：

- 是否存在孤立线条或未初始化元素。
- 标题/说明是否被主体遮挡。
- 所有文本是否完整可读，并在所属容器中按设计对齐。
- 画面文字是否只是字幕重复。
- 字幕是否进入主视觉。
- 主视觉是否进入字幕带。
- 连线是否准确连接到节点。
- 同一帧是否信息过密。
- shot 切换时是否有上一镜头残留。
- 结尾是否意外回到开头。
- 横竖比例是否发生非预期拉伸。

任何失败都回到 scene/layout 修复；不要靠最终剪辑软件把元素一个个拖开。
