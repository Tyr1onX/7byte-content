# Skill: Shot Design

## 输入
一个已经基本成立的口播脚本。

## 输出
4–10 个镜头；每个镜头写清：时间、主信息、稳定元素、主运动对象、因果关系、结束状态。

## 规则
- 开头 3–5 秒先建立问题，不先做品牌片头。
- 每镜只承担一个理解任务。
- 不为了切镜而切镜；如果空间关系应该连续，就让镜头延续。
- 新术语出现时给至少一次视觉锚点。
- 结尾尽量把抽象解释接回真实现象。
- 若某个细节会让第一期内容跑题，把它留给下一期，不用“为了严谨”把所有协议细节塞进来。

## 跨镜对象连续性硬规则

当同一个对象需要跨 shot 延续时，必须把“对象所有权”当成状态机处理，而不是只做淡入淡出：

1. **一个语义对象，同一稳定帧只能有一个可见 owner。** 禁止同时出现“设备卡片 + 另一个设备标签/代理”表达同一个东西。
2. transition proxy 只允许存在于明确的 handoff 窗口：`source → proxy/target → source 退场 → proxy 退场或成为 target`。
3. **所有 root-level proxy 必须显式结束生命周期。** 子 shot 的 `opacity=0` 不会自动隐藏位于其外部的 proxy；进入下一 shot 前必须单独把 proxy 设为不可见。
4. 下一 shot 已经有新的语义表示时，上一 shot 的 proxy 必须先退出，不能为了“连续”而残留到新画面。
5. 对象连续性不能牺牲信息层级；如果保持 proxy 会导致重复卡片、重复标签或拥挤，优先简化目标构图。
6. 每个 handoff 强制审计 `边界前 3 帧 / 边界帧 / 后 3 帧 / handoff 中点 / 下一镜头首个稳定帧`，检查：重复对象、幽灵残留、旧 connector、旧标签、下一镜头提前泄漏。
7. **Shot-end invariant：**所有临时 transition ref 在下一镜头稳定画面完全出现前必须满足 `opacity = 0`，除非它已经被明确声明为下一镜头的唯一 owner。
8. **同一语义对象改变抽象层级时先匹配几何，再交接外观。** source/target 的中心位置与外接框应先尽量接近，再交接 opacity；不要让“尺寸/纵横比跳变”和“模型替换”发生在同一帧。若 handoff 时宽或高相差约 15% 以上，优先重做目标节点比例或过渡，而不是用更快的淡化掩盖。
