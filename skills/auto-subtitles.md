# Skill: Auto Subtitles

## 目标

把最终旁白自动变成可直接导入剪映或烧录进视频的字幕，尽量减少手工对轴，同时避免字幕和画面文字互相重复或争抢空间。

这是剪映「识别字幕」之外的第二条正式字幕路线。两者二选一，不要求同时做。

## 首先判断旁白来源

### A. AI/TTS 旁白

**优先直接使用 TTS 自己产生的 speech-boundary / subtitle timestamps，不要再把同一段 AI 声音拿去 ASR 一遍。**

原因：
- 文本本来就是已知的，不存在“识别错字”这一层误差。
- TTS 引擎知道实际合成时的时间边界，对齐通常比重新转录更稳。
- 技术词可直接保持稿件写法，例如 `baidu.com`、`DNS`、`GET /`、`JavaScript`。

### B. 真人录音 / 外部音频

这时才使用真正的 ASR：OpenAI Whisper / Audio Transcription、开源 Whisper CLI，或 whisper.cpp fallback。输出 segment / word timestamps 后再做中文断句和术语校正。

## 自动字幕工作流

1. 获取最终旁白/成片。
2. 判断声音来源：TTS 读取合成边界；真人/未知来源使用 ASR。
3. 根据中文标点、自然语义单元和停顿重新切分 subtitle cue。
4. 技术 token 保持完整，不拆 `baidu.com` / `GET /` / `JavaScript` / `Wi-Fi` 等。
5. 执行**屏幕宽度检测**。
6. 执行**语义完整性检测**：不能为了视觉平衡在词中间、短语中间或依存关系中间换行。
7. 执行**字幕自身安全区检测**：左右不出屏。
8. 执行**字幕与正文空间契约检测**：字幕只能出现在 scene 预先留出的字幕带，不能覆盖 Motion Canvas 主视觉。
9. 执行**重复信息检测**：如果当前 cue 已被清晰、完整、可读的 Hook 大标题或 canonical 片尾文字承担，可以主动抑制这一条字幕。
10. 输出 `SRT`；需要验收时额外生成带字幕 demo MP4。
11. 渲染前运行 ASS 转义校验；渲染后抽查所有发生过拆分/换行的字幕帧。

## 字幕切分与换行规则

### 总原则

**先保持一句话/语义单元完整，再考虑视觉宽度。不要为了“看起来均匀”而换行。**

- 优先在句号、问号、分号、逗号和明确的自然停顿处分 cue。
- 不能按字符数或“左右两行差不多长”来强行平衡。
- 不能拆开一个完整词、技术 token、固定搭配或紧密短语，例如 `再看看` 不能变成 `再看` / `看...`。
- 不能让上一行/上一 cue 以一个明显未完成的短语结尾。
- 横版空间足够时，宁可保留一条较长但完整的单行字幕，也不要无意义换行。
- 只有单行确实超出安全宽度时，才在**自然语义边界**拆成下一条 cue；优先拆 cue，而不是在同一个 cue 内硬换两行。
- 如果必须两行，两行也必须各自形成自然阅读片段，不能只是机械平分字符。
- 技术 token 保持整体。
- 相邻 cue 不重叠。
- 字幕文本忠实于实际旁白。
- 字幕样式固定，不允许每条自己决定字号或位置。

## 16:9 横版默认策略

关系型解释视频使用 1920×1080 时，字幕空间明显比竖版宽松，因此采用：

- **默认单行优先。**
- 参考安全单行宽度约 `1500px`（具体字号/字体变化时重新测量），而不是继续沿用竖版较窄的宽度阈值。
- 一句在安全宽度内时禁止主动换行。
- 超宽时先按语义拆成两个连续 cue，例如：
  - `下次遇到这种情况，先试试其他网站，`
  - `再看看同一个 Wi-Fi 下，其他设备能不能上网。`
- 不允许为了填满第一行而把第二个完整动作的一半塞进上一行。
- 默认不写 ASS 强制换行 `\N`；确实需要两行时才显式使用。

### ASS 转义规则（回归阻断）

EP002 曾出现过 `\\N` 被写进 ASS 的问题。ASS 真正的强制换行只允许**单个反斜杠**的 `\N`；双重转义会把 `\` 作为可见字符渲染出来，导致字幕末尾出现多余反斜杠。

因此：

- 生成 ASS 后必须检查 Dialogue 文本中是否存在 `\\N`。
- 横版单行模式下，Dialogue 中不应存在任何 `\N`。
- 字幕正文里出现非预期 `\` 直接视为构建失败。
- 使用仓库脚本：
  - `node scripts/validate-ass-subtitles.mjs <file.ass> --single-line`
- 通过校验后才能进入 FFmpeg 烧录。

## 字幕与画面文字的职责分工

字幕负责让观众读到实际说了什么；画面文字负责解释实体、状态、关系和结构。

默认不要出现：
- 大标题完整写着一句口播，底部字幕又原样显示一次。
- canonical 片尾已经显示品牌名/口号，底部再叠一遍相同口号。
- 卡片说明句和字幕只是同义改写。

允许抑制 cue 的前提：
- 画面文字与该 cue 含义完整一致。
- 文字足够大、停留时间足够、不会被 UI 遮挡。
- 抑制后不会造成听障/静音观看者缺少关键信息。

EP002 当前做法：Hook 标题 cue 和 canonical 片尾品牌 cue 不再额外烧录字幕；正文解释仍正常保留字幕。

## 画幅与字幕带

字幕安全区必须和 `layout-safety.md` 同时使用。

### 当前 16:9 / 1920×1080 基准

- Motion Canvas 主视觉不得进入底部字幕保留带。
- 烧录字幕固定在底部保留带内，位置根据该期实际内容区确认；不能和正文重叠。
- 左右安全边距至少 `120px`。
- 默认字号约 `42–48px`；不因某条过长临时缩小。
- 横版优先单行；只有语义和空间都要求时才允许两行。

**重点：字幕“没出屏”还不够。字幕如果盖住了正文、破坏了语义，或者只是重复画面大字，也算失败。**

### 竖版 1080×1920（需要时）

如果某一期明确选择竖版：

- 左右安全边距优先 `100–120px`。
- 字幕整体上抬，参考 ASS `MarginV ≈ 320–370px`。
- 最多两行。
- 同样必须由 Motion Canvas 预先留出底部字幕空间。

## 渲染后字幕审计

所有发生过字幕拆分或强制换行的位置都必须抽帧检查：

- 是否出现 `\`、`N` 等转义残留。
- 是否在词语/短语中间断开。
- 上一个 cue 是否明显语义未完。
- 下一 cue 是否从一个孤立尾词开始。
- 横版是否存在“明明能单行，却硬拆两行”的情况。
- 字幕是否和主视觉重叠。

只检查 SRT/ASS 文本不够；必须看最终烧录后的画面。

## 两种正式字幕路线

### A. 7BYTE Auto Subtitle Skill

适用于希望减少剪映识别步骤、需要可复现字幕、后续继续自动化批量生产。

### B. 剪映「识别字幕」

适用于直接在剪映完成最终剪辑，且剪映识别效果已经足够好。

**不要为了流程完整而两套都做。** 每一期在 `publish.md` 记录最终用了哪一条。

## 存储策略

SRT、ASR verbose JSON、word timestamps、临时 WAV 都属于工作产物。默认不上传长期文件库，也不提交 GitHub；最终发布完成后可删除。只有确实需要长期复剪或跨软件迁移时，才保留最终 SRT。
