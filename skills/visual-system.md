# Skill: 7BYTE Visual System

## 目标

让 7BYTE 的视频逐渐形成稳定、舒服、能被识别出来的视觉语言，同时不牺牲知识解释的清晰度。

核心不是堆装饰，而是让观众在几秒内感知到：这是 7BYTE 的内容，而且信息关系很好读。

## 1. 品牌层级

正文阶段默认允许两个稳定品牌元素：

1. **左上角 Brand Bug**
   - 使用权威抖音头像 + `7BYTE`。
   - 小尺寸、低存在感，不做宣传口号，不重复字幕。
   - 位于最上层 UI，但必须避开标题和平台安全区。
   - 正文阶段持续存在；进入 canonical 片尾前淡出。

2. **背景 7BYTE 水印**
   - 大号、极低透明度。
   - 只承担背景纹理和品牌气质，绝不能影响正文对比度。
   - 默认约 2%–4% 视觉强度，最终以实际截图审计为准。

canonical 片尾保持独立，不要在片尾再叠 Brand Bug。

## 2. 视觉方向

7BYTE 默认采用：**安静的技术编辑风 / 教材插图 × 操作系统 UI × 极简 Motion Graphics**。

避免：
- 蓝紫 AI 渐变。
- 玻璃拟态堆叠。
- 无意义粒子、光晕和背景噪点。
- 为“科技感”添加不参与解释的线条。
- 每个镜头都换一种 UI 风格。

鼓励：
- 黑 / 炭黑背景。
- 暖白正文。
- 荧光黄绿色作为主要动作与“可达 / 正常 / 当前关注”的语义色。
- 蓝色用于网络 / 外部系统。
- 红色仅用于失败 / 中断 / 警告。
- 统一圆角、描边、间距、字体层级。

## 3. 画面文字不能成为第二套字幕

字幕负责完整表达口播；画面文字只承担：

- 实体名。
- 状态。
- 关系。
- 对比。
- 决策结果。
- 必要图例。

如果一行画面文字删掉后，观众仍能通过图形关系 + 字幕理解，那么优先删掉。

## 4. 组件优先于临时手画

能使用成熟图标 / Motion Canvas Layout / 响应式 connector，就不要用手写绝对坐标去模拟。

默认：
- 图标优先 Lucide / Iconify。
- 节点优先统一卡片组件。
- connector 端点绑定节点几何。
- 横向链路优先用 Layout / 固定网格组织。
- 同一种实体在不同镜头保持相同视觉语言。

## 5. 动效规则

动效必须服务因果关系。

- 同一时刻只突出一个主要变化。
- 常规 transition 约 0.8–1.4s；具体以口播节奏为准。
- 节点出现后，连接线再生长；不要先出现孤立线条。
- 状态变化优先通过 stroke / icon / 小范围位移表现，不让整个 UI 乱跳。
- 不为了“看起来有动画”而让所有东西持续漂移。

### 瞬态对象必须有完整生命周期

凡是 packet、光标、请求标记、状态提示、临时高亮等“出现一会儿再离开”的元素，不能只定义中间动作。

默认必须同时设计：

1. **进入**：淡入、从源节点发出、轻微 scale / opacity 过渡等。
2. **作用**：移动、聚焦、状态变化，真正承担当前因果解释。
3. **离开**：被目标节点吸收、淡出、缩回或自然退场。

禁止：
- 到时间点瞬间 pop in。
- 动作结束后瞬间消失。
- 仅因为 `enable / opacity` 时间窗口结束就把对象硬切掉。

对象连续性优先于“动画数量”。如果一个瞬态对象没有自然进入和离开，就宁可先不用。

## 6. 舒适度检查

每个镜头需要同时通过：

- 主体层级清楚。
- 空白足够。
- 字幕不挤主视觉。
- 画面文字不重复口播。
- 对比度足够但不过曝。
- 品牌元素能被看到但不抢内容。
- 连线端点准确。
- 同一镜头没有多个争夺注意力的高亮色。
- 瞬态对象的出现和消失没有突兀跳变。

## 7. 最终视觉审计

最终视频必须抽取关键帧 contact sheet，并让视觉模型/人工检查：

- Brand Bug 是否和标题、主 UI 重叠。
- 水印是否过强。
- 是否仍有孤立线 / 悬空 connector。
- 节点尺寸和间距是否稳定。
- 文字层级是否舒服。
- 是否存在 UI 与字幕重复。
- 是否有某个镜头明显比其他镜头粗糙。
- 所有瞬态对象都要额外检查“出现前 / 动作中 / 消失前后”，不能只截中间一帧。

发现问题必须回到组件 / shot / 布局层修复，不在最终视频上靠临时遮罩掩盖。

## 8. 迭代原则

视觉系统允许长期演化，但每次只把**经过实际视频验证**的规则提升为全局规则。

一期里的实验先留在 episode 内；连续多期都有效后，再提升到 shared / skill。


## 9. Shot ownership：禁止跨镜头提前泄漏

每一个可见 primitive（点、线、图标、chip、packet、状态标记）都必须有明确的当前镜头语义归属。

- 不允许为了后续动画方便，把下一 shot 的元素提前放在当前 shot 且默认可见。
- 临时元素默认 `opacity=0`，只能由所属 shot 的时间线显式激活。
- 无 ref、无生命周期、无法说明信息角色的装饰 primitive 默认视为风险项。
- 最终视觉审计必须覆盖所有 shot boundary：切换前、边界、切换后，而不仅是每个镜头的中间关键帧。
- 发现“提前出现/上一镜头残留”时回到 scene ownership 修复，不用遮罩掩盖。
