# 7BYTE 固定视频工作流

这份文档是 7BYTE 后续每一期视频的默认生产流程。除非明确决定升级品牌/流程，否则新视频按此执行，不重新发明一套做法。

## 0. 每一期必须留下记录

每个 `episodes/<episode>/` 必须有：

- `idea.md`：本期核心问题与观众要记住什么。
- `script.md`：最终口播稿。
- `storyboard.md` / `animation-spec.md`：动画设计与时间轴。
- `cover/cover.json`：本期封面内容配置。
- `publish.md`：最终发布记录（标题、简介、话题、封面、声音、成片、发布日期等）。

发布后不删除历史记录；若后续重发/修改，在 `publish.md` 追加新版本。

## 1. 选题

先确定一个观众能立刻理解的问题：

> 这条视频到底回答什么？

一条视频只解决一个主问题，不为了“完整”堆过多知识点。

## 2. 口播稿

- 先把内容写到单独听也能理解。
- 使用自然口语，不像教材朗读。
- 先保证表达舒服，再决定最终时长，不机械卡 60 秒。
- 技术术语保持准确，例如 DNS / HTTPS / HTTP / HTML / CSS / JavaScript。

## 3. AI 人声

- 先选定最终声音，再做最终动画 timing。
- 不在已经带声音的视频上重复叠加新声音。
- 每一期在 `publish.md` 记录实际使用的 voice / rate。
- EP001 当前基准声线：`zh-CN-YunyangNeural`。

## 4. Motion Canvas 动画

- 以最终人声为时间轴调整画面，而不是平均分配秒数。
- 动作本身保持利落，时长主要通过关键状态停留来匹配口播。
- 一次只强调一个主运动对象。
- 每个动画都必须帮助解释因果，不为了“科技感”而动。
- 最终正文：`1080×1920 / 60fps`。

## 5. 固定动态片尾

**唯一权威版本：EP001 V5 已认可成片中的片尾。**

- 长期文件库：`/7BYTE/brand/7BYTE-outro-canonical-from-EP001-V5.mp4`。
- 后续视频直接复用，不重新生成、不根据描述复刻。
- 头像尺寸、圆环、7 个 Byte 方块、`7BYTE_`、标语、终端提示、位置、节奏全部冻结。
- `shared/brand/outro-template.py` 只能复制 canonical 资产，不能设计新片尾。

## 6. 字幕与剪映

默认不在程序化视频里烧字幕。

成片导入剪映后：

1. 使用最终 AI 人声执行「识别字幕」。
2. 检查明显识别错误、断句和技术词。
3. 统一字幕字体、字号、位置。
4. 需要时再加 BGM / 音效 / 极少量最终剪辑。

字幕审阅器保留为备用工具，但不再作为默认必经步骤。

## 7. 固定封面系统

每一期必须同时准备 **两张封面**：

### 竖封面
- 比例：`3:4`。
- 用于抖音竖封面入口。

### 横封面
- 比例：`4:3`。
- 用于抖音横封面入口。

### 两张封面的共同规则

固定：
- 黑/炭灰背景。
- 暖白主文字。
- `#D8FF68` 荧光绿作为少量强调。
- 使用唯一权威抖音头像 + `7BYTE` 品牌标识。
- 版式简洁、高对比、第一眼能读懂。

每期变化：
- 本期核心问题/标题。
- 与本期内容直接相关的一个主视觉。

禁止默认加入：
- `EP001 / EP002` 等编号。
- `INTERNET / SERIES` 等系列标签。
- 无意义角标、分类标签、装饰性小字。
- 大量流程文字或为了显专业堆信息。

封面的判断标准只有一个：**缩小后，观众一眼能知道这条视频讲什么。**

## 8. 发布信息

发布前必须确定并写入本期 `publish.md`：

- 作品标题。
- 作品简介。
- 话题标签（一般 3–5 个，相关性优先）。
- 合集（如适用）。
- 自主声明/AI 内容标记（按平台实际选项处理）。
- 竖封面文件。
- 横封面文件。
- 最终成片文件。
- 发布日期。
- 发布链接（能获取后补上）。

### 文案原则

- 标题直接回答“这条视频讲什么”，不要标题党到失真。
- 简介用 1–3 句补充价值，不重复整段口播。
- 话题只放真正相关的，不蹭无关热词。
- 不为了填满平台字段增加多余信息。

## 9. 发布前检查

- [ ] 最终视频 1080×1920 / 60fps。
- [ ] 只有正确的一条主旁白轨，不存在叠音。
- [ ] 没有程序内旧字幕残留。
- [ ] 剪映识别字幕已检查技术词。
- [ ] 使用 canonical 片尾，没有旧版/临时片尾残留。
- [ ] 竖 3:4 和横 4:3 两张封面都已准备。
- [ ] 两张封面没有 episode 编号、系列标签等冗余信息。
- [ ] 标题、简介、话题已记录到 `publish.md`。
- [ ] 成片和封面已存长期文件库，不只存在 `/mnt/data` 临时目录。

## 10. 存储规则

- **GitHub**：长期保存可复现源文件、品牌规则、封面模板/配置、每一期创作与发布记录。
- **ChatGPT 文件库**：保存最终成片、封面导出图、canonical 片尾等二进制发布资产。
- **`/mnt/data`**：仅是当前 ChatGPT 工作环境临时副本，不能视为长期存储。
- **用户电脑本地**：剪映/发布工作副本；用户下载后才真正存在本地磁盘。
