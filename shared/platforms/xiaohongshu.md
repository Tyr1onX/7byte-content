# 小红书平台规则

## 当前定位

7BYTE 在小红书不做“男性科技号”或“女性科技号”，也不做普通数码种草号。

当前定位：**解释你每天都在用，却很少有人真正讲清楚的科技。**

目标是先用真实数据验证科技科普在小红书的需求，再决定后续商单、商品分佣、自有产品导流等变现方向。

当前阶段：冷启动测试。

## 发布节奏

- 每周 3–4 篇。
- 稳定优先于短期日更。
- 前 20–30 篇承担赛道验证任务，不因前几篇数据普通就频繁换方向。

## 内容支柱（初始假设，需被数据验证）

- 40%：生活中的科技原理。
- 25%：计算机 / 网络基础。
- 15%：数码原理与避坑。
- 15%：AI / 软件工具。
- 5%：7BYTE 品牌 / 互动 / 实验性内容。

这不是永久配比。累计足够样本后，按收藏、搜索来源、精准评论、关注转化等真实数据调整。

## 表达原则

1. 从“生活里遇到的问题”进入，不从教科书定义进入。
2. 第一张图优先回答“为什么我要继续看”，正文负责兑现，不用夸张营销话术。
3. 图文以 3:4 知识卡为主；优先 6–9 张，具体页数由内容决定。
4. 一张卡只承担一个主要信息，不把短视频字幕截图直接当小红书图文。
5. 保留搜索关键词，但正文首先要自然、可读。
6. 收藏价值优先于堆知识量：读者以后遇到问题时愿意回来找，比一次塞满所有细节更重要。
7. 不编造亲身经历、使用时长、互动数据或身份背书。
8. 前期不硬塞带货和导流；商业内容必须从真实的问题解释自然延伸。
9. 图内只放用户真正需要看的内容；创作者自己的推理、边界备注、防御性解释不直接进入成品图。

## 静态视觉生成

小红书**显式接入** `shared/visual/ai-still-image-workflow.md`。

当前默认视觉工具链：

```text
选题 / core
→ 小红书平台文案
→ visual-brief.md
→ gpt-image-2-style-library 选模板
→ Image2 生成候选
→ 人工审阅
→ 发布
→ metrics.md 复盘
```

### 模板默认值

- 首图 / 封面：优先 `poster-layout-system`。
- 正文知识卡 / 技术图解：优先 `infographic-engine`。
- 需要校准品牌触点时：参考 `brand-identity-package` / `brand-touchpoint-board`。

### 冷启动封面策略

冷启动阶段，重点选题默认先准备 2–3 个封面方向，再人工选择最终发布版本：

1. 强问题型。
2. 反常识型。
3. 场景代入型。

这不是要求一次发布多个版本，而是用低生成成本提高最终首图质量，并逐步记录哪类封面带来更好的点击表现。

### 品牌与一致性

- 需要出现 7BYTE 头像 / Logo 时，必须使用官方品牌资产作为参考图，禁止模型自行重画近似猫头像。
- 同一篇多页图文的品牌位、页码、字体层级、主要配色必须统一。
- 当前小红书可继续测试黑 / 白 / 电光蓝等高对比静态视觉，但**这只是小红书平台实验，不自动同步为抖音视频视觉规范**。
- 可以复用抖音已经验证过的知识表达、品牌资产和优秀构图经验，但不得为了“统一”去改变成熟的短视频动画生产链路。

### 图内文案

避免在图片中出现制作备注式语言，例如：

- “这里先只讲……”
- “不强制限定……”
- “这篇先把主链路串起来……”
- “下一篇再展开……”

事实边界需要保留时，改写成自然、简短、用户可理解的准确表达。

## 首轮选题方向

当前优先验证：

1. 输入 `baidu.com` 后发生了什么？
2. Wi-Fi 满格为什么还是上不了网？
3. 为什么换 DNS 有时网站突然能打开？
4. HTTPS 到底保护了什么？
5. 手机显示 5G，为什么网速仍然很慢？
6. 文件删除以后真的消失了吗？
7. 为什么重启能解决很多电脑问题？
8. TCP 为什么需要三次握手？
9. HTTP / HTTPS / TCP / IP 到底是什么关系？
10. Type-C 长得一样，里面到底差多少？

后续选题继续从评论和数据中补，不把这份清单当永久排期。

## 复盘指标

前期不只看点赞。优先记录：

- 曝光 / 阅读
- 封面点击表现（后台可得时）
- 收藏率
- 评论是否出现精准追问
- 主页访问与关注转化
- 搜索来源 / 搜索词（后台可得时）
- 不同内容支柱之间的相对表现
- 不同封面类型之间的相对点击表现（有足够样本后再判断）

单篇数据写入 `episodes/<episode>/platforms/xiaohongshu/metrics.md`。

## 外部 Skill

内容方法默认参考：`SpaceZephyr/creator-buddy` → `xhs-Skills`。

视觉模板默认参考：`freestylefly/awesome-gpt-image-2` → `gpt-image-2-style-library`。

推荐工作流：

```text
明确选题
→ space-xhs-writer
→ space-xhs-title
→ visual brief
→ gpt-image-2-style-library 选择视觉模板
→ Image2 生成 / 编辑
→ 人工审阅
→ 发布
→ space-xhs-note-analytics / metrics 复盘
```

有明确选题时不要为了形式强行跑 hotspot。涉及真实热点和竞品数据时，必须确认数据源可用；没有真实数据就明确标注“未经数据验证”，禁止编互动量。

外部 Skill 只作为创作方法与工具，不复制完整外部仓库到本仓库。7BYTE 自己通过数据验证出的结论再沉淀到本文件。
