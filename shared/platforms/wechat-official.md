# 微信公众号平台规则

当前状态：**预留的深度长文层，不要求每个选题同步。**

## 默认策略

- 只有当某个选题值得展开背景、完整推理、更多例子或可长期检索时，才制作公众号版本。
- 文章从 episode 的 core 出发，不直接把短视频口播稿扩写成“更长的口播”。
- 可以补充短视频刻意省略的概念，但新增事实必须重新核验。
- 标题、摘要、排版和 CTA 属于公众号层，不写入 core。

## 公众号 DOCX 兼容性硬规则

公众号后台的 DOCX 导入兼容性优先于 Word 视觉效果。交付前必须遵守：

- 正文固定为单栏线性内容流。
- 允许：标题、普通段落、加粗、有序/无序列表、简单引用、单张图片、图片说明。
- 禁止使用表格做视觉布局或步骤卡片。
- 禁止分栏、文本框、浮动形状、复杂图文环绕、固定高度卡片、大面积单元格底色。
- 需要流程图、步骤卡、复杂信息卡时，先渲染成一张普通图片，再作为单张图片插入正文；不得依赖 Word 版式模拟。
- DOCX 创建后必须执行 render → 逐页视觉检查；发现挤压、溢出、蓝色大块、表格变形等风险必须修复后重新渲染。
- 兼容性和可读性优先，不为了“更好看”引入公众号导入器不稳定的结构。

## 封面硬规则

- 公众号消息列表主封面比例永久锁定为 **2.35:1**。
- 标准交付尺寸固定为 **1175×500 px**，禁止用近似比例替代。
- 每次生成后必须检查实际像素尺寸，不得只凭肉眼判断比例。
- 关键标题、品牌标识和核心主体要留在中央安全区域，兼顾聊天/朋友圈等场景的 1:1 中央裁切。
- 正文长图、DOCX 页面预览图、拼接教程图禁止作为公众号主封面。

## 交付文件命名硬规则

- 用户最终上传公众号的 DOCX 文件名必须 **与最终文章标题完全一致**，仅追加 `.docx` 扩展名。
- 封面文件名同样使用最终文章标题，仅追加图片扩展名。
- 禁止在最终交付文件名中加入 `01`、`02`、`03`、`稳定版`、`最终版`、`含截图`、`修复版`、`公众号版` 等内部工作标记。
- 禁止为了内部管理擅自改写、缩短或追加标题。内部版本信息只能存在工作目录或 Git 记录中，不能进入最终上传文件名。
- 生成文件前先锁定最终文章标题；后续 DOCX、封面、摘要都围绕同一个标题生产。

## 单篇交付默认包

每篇公众号内容默认交付：

1. 与最终标题同名的 `.docx` 正文；
2. 与最终标题同名的 `1175×500` 主封面；
3. 一条可直接粘贴的摘要；
4. 如确实需要真实操作界面截图，只向用户索取完成文章所需的最少截图，并说明每张截图的用途。

## 单篇目录

```text
episodes/<episode>/platforms/wechat-official/
├─ article.md
├─ publish.md
└─ metrics.md
```

未来启用公众号后，再根据真实后台数据补充标题、打开率、阅读完成、分享等复盘规则。
