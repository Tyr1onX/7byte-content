# 抖音 / 通用短视频平台规则

## 定位

7BYTE 的短视频主线：把计算机、网络、软件和数码原理讲简单，优先解释观众每天正在使用但没真正理解的东西。

## 内容层与制作层

- `core.md` / `idea.md` 决定讲什么。
- `script.md` 决定口播节奏。
- `storyboard.md` / `animation-spec.md` / `src/` 决定画面与动画。
- `publish.md` 记录最终发布版本。

短视频规则不得反写到 core：例如“前 3 秒 Hook”“60 秒”“竖版/横版”“片尾 CTA”都属于平台/制作约束，不属于知识事实。

## 现有长期原则

- 口播单独听也必须能理解。
- 动画服务解释，不为科技感而动。
- 对关系、链路、对比型内容，优先空间稳定、对象关系连续。
- 真实 UI 只有明显增加可信度时才使用。
- 发布前必须完成视觉审计；Build/CI 成功不等于视觉通过。
- 标题和简介可以适应平台，但不得夸大事实或编造体验。

具体视频生产流程继续以 `docs/workflow.md`、`docs/motion-design.md`、`skills/` 和 `shared/brand/` 为准。

## 与 AI 静态图片工作流的边界

`shared/visual/ai-still-image-workflow.md` 是跨平台可复用的**静态视觉工具层**，但抖音 / 通用短视频当前**不默认接入它作为视频生产主流程**。

因此：

- 不因为引入 `awesome-gpt-image-2` / `gpt-image-2-style-library` 而改写 Motion Canvas 场景、动画、字幕、镜头或品牌锁。
- 不把小红书当前测试中的黑 / 白 / 电光蓝静态卡片风格迁移成视频默认视觉。
- 不用 AI 生图替换已经稳定的 SVG、真实 UI、Motion Canvas 对象关系和横版品牌层。
- 只有某一期明确需要独立静态插图、概念图或封面实验，并且现有 `skills/cover-design.md` / 品牌规则允许时，才可以显式调用共享 AI 静态图片工作流。
- 即使调用，最终视频封面与成片仍以抖音自己的视觉审计、画幅和品牌规范为准。

可以跨平台复用的是：知识母稿、官方品牌资产、经过验证的解释方式和构图经验；不能为了形式统一而破坏已经验证稳定的视频生产链路。
