# Design Notes — 插电但停在 80%

## 数据驱动目标
EP014 约发布后 46h：1022 播放、2s 跳出 36.99%、5s 播放率 21.35%、平均播放 5.25s、平均播放占比 14.06%。EP015 把实验变量从“可见异常场景”继续收紧成“单一数字冲突 + 立即答案”：`PLUGGED IN ✓ / 80% / NOT CHARGING`。

## 画幅与空间
`1920×1080 / 60fps`。主视觉保持在 `y=-360..300`，底部字幕带不放关键卡片。canonical header / watermark / outro 完全复用。

## Hook
第一稳定帧直接同时出现：
- 插头已连接；
- 大号 `80%`；
- `NOT CHARGING`；
- 结论 `不一定是电池坏了`。

口播第一句必须完整交付：`插着电却停在80%，不一定是电池坏了。`

## 视觉路线
1. 插电 + 80% + NOT CHARGING。
2. `SMART CHARGING / CHARGE LIMIT`：100% 上限被下调到较低目标。
3. `不同厂商 ≠ 同一阈值`：强调 80% 不是统一标准。
4. 行动选择：`马上出门 → 临时满充` / `长期插电 → 保持限制`。

## 本期实验
- 保持约 48h 发布节奏，避免同时改变分发节奏。
- 不增加第二个技术故事，只解决“为什么停在 80%”一个问题。
- 目标正文约 22–25s，完整成片约 27–30s。
- 目标：2s 跳出 `<30%`；5s 播放率 `>45%`；平均播放时长回到 `>7s`。

## Production 决策
- V1 Production Build `34838406620` 全流程通过，但正文约 `28.197s`、完整成片约 `32.817s`，超过本期主动缩短时长的实验目标，因此不作为最终候选。
- V2 主动删减口播冗余，Production Build `34838813887` 全流程通过。
- V2 正文结束 / canonical outro 起点 `23.696708s`，完整成片 `28.316667s`，落入预设的 `27–30s` 区间。
- V2 shot boundaries：`4.750s / 12.842s / 15.697s`。第一段完整回答在 5 秒内交付；行动选择约 15.7 秒进入。
- V2 作为本期 Final Candidate，等待用户人工看片确认。
