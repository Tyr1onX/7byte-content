# EP003 Design Notes

## 本期视觉目标

这期不继续增加网络拓扑复杂度，而是验证一件事：**只靠数字、单位和一个清晰的 8→1 转换，能不能把知识点讲得比复杂流程图更快、更稳。**

核心视觉记忆只有两个：

1. `8 bit = 1 Byte`
2. `1000 Mbps ÷ 8 = 125 MB/s`

任何不帮助这两个认知成立的装饰动作都删掉。

## 画幅与空间契约

- 正文：`1920×1080 / 16:9 / 60fps`。
- 主视觉优先保持在约 `y=-360..280`。
- 底部约 `y=320..500` 作为字幕保留带，正文实体与说明文字不得进入。
- 平台 UI 避让仍按横版安全区处理；重要数字和单位不贴边。
- `project.meta`、capture viewport、最终输出必须完全一致。
- 正文背景保留非常淡的 `7BYTE` 大字水印，作为最底层静态背景，不为水印移动正文。

## 视觉语言

沿用已冻结品牌基线：

- Background: `#111210` / 接近炭黑。
- Surface: `#1B1D1A`。
- Primary text: `#F3F1E8`。
- Secondary text: `#A7AAA1`。
- Accent: `#D9FF6A` / `#D8FF68`。
- 红色只用于确实需要表达错误；本期原则上不需要故障红。

禁止默认加入：蓝紫渐变、glow、玻璃拟态、粒子网络、无意义赛博网格、快速旋转或闪白。

## 数字与单位层级

本期主角是数字，因此数字排版必须比普通 UI 更严格：

- `1000`、`125` 是一级视觉对象，使用大字号、稳定字宽与充分留白。
- `Mbps`、`MB/s` 与数字保持明确绑定，但视觉权重略低于数字本身。
- `b` 与 `B` 在解释单位时可以单独高亮；不得靠整段说明文字解释大小写差异。
- `÷ 8` 必须作为关系对象，而不是普通正文。
- 技术 token 不拆开，不把 `MB/s` 换行成 `MB` 与 `/s`。

## 8 bit → 1 Byte

这是本期唯一需要稍具“招牌感”的动画。

- 使用 **8 个**等尺寸、简单、非发光的小单元表示 8 bit。
- 8 个单元先完整建立，再聚合/归组到一个 `1 Byte` 容器或统一外框中。
- 不使用 EP002 的 7-byte packet 组件或 7 个方块外观，避免品牌视觉与知识语义冲突。
- 聚合过程必须让观众看清“8 变 1”的关系，不能 0.2 秒内瞬间完成。
- 结果 `8 bit = 1 Byte` 保留阅读停顿。

## Shot / transition 原则

- 本期没有必要用多套拓扑，因此默认不用复杂 handoff proxy。
- 跨镜延续的数字优先在原位做 matched-geometry：先对齐中心和外接框，再改变大小/上下文。
- 若为了实现过渡引入临时 proxy，仍执行“一语义对象、一可见 owner”和完整退休生命周期。
- 一次只有一个主运动对象；辅助高亮、淡入可以同时存在，但不能争抢注意力。
- 重要结果出现后至少留出正常阅读时间，不做连续机械飞入。

## 画面文字职责

旁白 + 字幕负责完整句子；画面只保留：

- 数字：`1000` / `125` / `≈100`。
- 单位：`Mbps` / `MB/s`。
- 关系：`8 bit = 1 Byte` / `÷8`。
- 状态：`理论上限` / `实际下载`。
- 影响因素实体词：`协议开销`、`服务器`、`网络链路`、`设备`。

禁止再出现全局 headline 每句跟着口播改字，也不放解释段落作为第二套字幕。

## “约 100MB/s”如何表达

Hook 中 `≈100 MB/s` 只是一个常见现象示例，不把它表现成所有千兆宽带都必须达到的固定值。

最终模型只做确定性结论：

`1000 Mbps ÷ 8 = 125 MB/s（理论换算值）`

然后用：

`实际下载 < 理论值`

表达现实损耗。协议、服务器、网络链路和设备只作为影响因素，不在本期继续拆解。

## 字幕与人声

- 当前默认 AI 人声仍使用 `zh-CN-YunyangNeural`。
- 字幕默认走 `7BYTE Auto Subtitle Skill`。
- TTS timing 是 scene 时间轴唯一 source of truth。
- 横版默认单行字幕优先；只有真实像素宽度超限才按自然语义拆 cue。
- Hook 若大标题已经完整显示问题，可抑制对应字幕；正文解释正常保留字幕。

## 封面方向

两张封面必须分别布局：3:4 与 4:3。

核心关系只保留：

`1000M → 125MB/s`

或

`1000M 为什么只有 100MB/s？`

主视觉优先是“大数字 + ÷8 / 8 bit → 1 Byte”的直接关系，不画路由器、服务器等无关对象。

封面使用实际 bounding box 布局；禁止固定百分比坐标猜文字位置。生成后分别检查原尺寸、50%、25% 缩略图。

## 强制视觉审计

最终渲染后必须运行 `scripts/audit-video-visual.sh`，重点检查：

- 0–1 秒数字/符号是否有提前泄漏。
- `b` / `B` 高亮是否清楚但不过度夸张。
- 8 个 bit 是否完整、等距、无重叠。
- 聚合为 Byte 时是否真的看得出 8→1。
- `1000 → ÷8 → 125` 是否在任何关键帧都不互相覆盖。
- 字幕是否始终停留在预留字幕带。
- Shot 边界是否出现数字双影、旧单位残留或 proxy 未退休。
- 最终 2 秒保持正确模型，不 loop 回 Hook。
- canonical 片尾只等比适配，不重绘。

## V2：首轮视觉审计修正

V1 首次 1920×1080 / 60fps 实际渲染通过，但视觉审计发现四类问题：

1. Shot 1→2、Shot 2→3 在末尾预先 fade-out，下一 shot 又从 opacity 0 开始，产生纯背景空档。
2. Shot 3→4、Shot 4→5 的渐隐/渐入在采样帧中形成两套信息叠在一起的 muddy frame。
3. Shot 4 的圆头进度线在 `end=0` 时仍渲染为一个绿色小点，属于提前泄漏。
4. 多个顶部标题仍然完整复述旁白，且核心 `8 bit → 1 Byte` 视觉比例偏小。

V2 处理：

- 这些镜头没有必须连续的同一语义对象，因此改为**干净的语义切镜**：边界时前一 shot 立即退场、后一 shot 立即获得 owner，动画只发生在 shot 内部。
- 进度线增加显式 opacity 生命周期，正式增长前保持不可见。
- `单位换算` / `理论换算 vs 实际下载` / `换算关系` 只承担结构标题，不再复述整句旁白。
- `8 bit = 1 Byte` 的 8 个 bit 单元、Byte 外框和最终等式整体放大，强化本期唯一核心视觉记忆。
- 现实因素收敛为本版旁白实际提到的 `协议开销 / 服务器 / 设备`。

V2 必须重新渲染并重新执行同一组边界帧审计，不能沿用 V1 contact sheet。
