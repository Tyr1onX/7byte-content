# EP003 Storyboard

> 时间只写相对阶段。最终时长与切点必须由最终 TTS timing 驱动。

## Shot 1 — Hook：1000M vs 100MB/s

**主信息：** 两个看起来差十倍的数字其实用了不同单位。

- 稳定元素：左侧 `1000 Mbps`，右侧下载面板 `≈100 MB/s`。
- 主运动对象：中间的 `?` / 对比关系，不做网络拓扑。
- 口播对应：`1000M 宽带，为什么下载软件里只有 100MB/s 左右？是不是运营商缩水了？`
- 结束状态：两个单位同时清晰停住，观众注意到 `b` 与 `B` 不同。
- Hook 标题已经完整承担问题时，对应字幕 cue 可抑制，避免重复。

## Shot 2 — 单位拆解：bit ≠ Byte

**主信息：** 小写 `b` 与大写 `B` 代表不同单位。

- 从 `Mbps` / `MB/s` 中只高亮 `b` 与 `B`。
- `bit` 与 `Byte` 作为技术 token 出现，不堆整句解释。
- 主运动对象：8 个等尺寸 bit 单元依次建立，随后聚合成 1 个 Byte 容器。
- 关键停留：`8 bit = 1 Byte` 至少保留足够阅读时间。
- 不复用 EP002 的 7-byte packet 外观，避免“7 个方块”品牌动作与“8 bit”知识点产生歧义。

## Shot 3 — 换算：1000 ÷ 8 = 125

**主信息：** 1000 Mbps 转成 MB/s 必须除以 8。

- 稳定结构：`1000 Mbps → ÷ 8 → 125 MB/s`。
- 主运动对象：数字从 `1000` 经过除法关系收敛为 `125`。
- `÷8` 是本镜唯一强调关系。
- 结束状态：`125 MB/s` 成为画面视觉重心，并标记为“理论上限”。

## Shot 4 — 理论值 vs 实际值

**主信息：** 实际下载低于 125 MB/s 并不等于带宽被砍掉九成。

- 左/上：`理论上限 ≈125 MB/s`。
- 右/下：`实际下载 < 理论值`，用一个示意下载条停在约 100MB/s 附近。
- 辅助因素只保留简短实体词：`协议开销`、`服务器`、`网络链路`、`设备`。
- 不展开每个因素，不画新的网络拓扑。
- 主运动对象：下载条从理论值轻微回落到实际示意值。

## Shot 5 — Final Model

**主信息：** `Mbps ≠ MB/s`，换算要 `÷8`。

- 最终模型：
  - `运营商：Mbps`
  - `下载软件：MB/s`
  - 中间：`÷ 8`
- 可补一行短结论：`1000 Mbps → 理论约 125 MB/s`。
- 最后稳定停留后进入 canonical 片尾。
- 正文结束后不得 loop 回 Hook。

## Shot ownership / continuity

- 本期尽量避免跨 shot 复用复杂实体，因此不主动引入 handoff proxy。
- 若 `1000 Mbps` 或 `125 MB/s` 跨镜延续，优先 matched-geometry 原位延续；任何 proxy 必须在下一镜稳定前完全退休。
- 每个 shot 边界仍执行 `-3 / -1 / boundary / +1 / +3` 帧审计，检查提前泄漏、重复数字、残留符号和旧文字。
