# Design Notes — 500 Mbps ≠ 低延迟

## 数据驱动目标
EP016 约44h曾达到约 1.03 万播放，但 2s 跳出 38.77%、5s 播放率 27.10%，说明“大众异常现象”能放大分发，答案交付仍需更快。

EP017 约84h只有 1147 播放，2s 跳出 53.42%，前两秒冲突建立不足。

EP018 已完成“100% / 3.2MB/s”数字悖论实验并合入，但仓库尚未回填发布后数据，因此 EP019 不根据未知的 EP018 成绩做推断，只延续已验证的“强矛盾 + 快答案”方向。

## 本期唯一实验变量
**答案在前 3 秒完整交付。**

- 第一稳定帧直接给 `DOWNLOAD 500 Mbps / PING 180 ms / 500 Mbps ≠ 低延迟`。
- 第一口播不是先问问题，而是直接说“很快，不代表延迟低”。
- 后续只负责解释和告诉观众测速还要看什么。

## 画幅与空间
- `1920×1080 / 60fps`
- 主视觉保持在 `y=-360..300`
- 底部字幕带不放关键卡片
- canonical header / watermark / horizontal outro 完全复用

## 视觉路线
1. 下载 500 Mbps 与 Ping 180 ms 的数字冲突。
2. Throughput 与 Latency/RTT 两张并列卡，只解释“每秒传多少”与“一次往返等多久”。
3. Speed Test 四指标面板：Download / Latency / Jitter / Packet Loss。
4. 两个“同样 500 Mbps”的示意连接，不同实时网络质量得到不同体验。

## 主动限制
- 不使用“高速公路”长类比占用大量时间，只保留指标本身。
- 不给固定 ping 阈值，避免把不同游戏、服务器和地区一刀切。
- 不把游戏卡顿全部归因于网络。
- 不增加 Wi‑Fi/QoS/运营商路由等第二故事。

## Production 迭代
- V1 Build `37260303320` 全绿，但第一答案边界 `3.407875s`，未达到 `<3s`；body `27.920375s`、final `32.533333s`，主动淘汰。
- V2 继续压缩第一句和重复解释，不改视觉结构，避免为了时长重做无必要镜头。

## 目标
- 第一答案：< 3s
- 完整成片：约 24–28s
- 2s 跳出：<35%
- 5s 播放率：>30%
- 平均播放：>6s
