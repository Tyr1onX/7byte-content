# Design Notes — 500 Mbps ≠ low latency

## 数据驱动目标
EP016 约44h：播放约1.03万，但 2s 跳出 38.77%、5s 播放率 27.10%、平均播放 5s。
EP017 约84h：播放 1147、2s 跳出 53.42%、5s 播放率 12.50%、平均播放 3s。
EP018 已完成最终候选并合入 main，但发布后数据尚未回填。

因此 EP019 不根据 EP018 的未知成绩做推断，只延续已经确认的方向：大众场景、首帧强冲突、答案前置。

## 本期唯一实验变量
**前 3 秒完整交付答案。**

不是先问“为什么”，而是直接说：
“测速五百兆，打游戏照样能卡。因为五百兆说的是下载吞吐量，不是延迟。”

## 画幅与空间
- `1920×1080 / 60fps`
- 主视觉保持在 `y=-360..300`
- 字幕带保持物理分离
- canonical header / watermark / horizontal outro 完全复用 EP002 金标

## Hook
第一稳定帧：
- `DOWNLOAD 512 Mbps`
- `PING 180 ms`
- `500M ≠ 低延迟`

不做数字逐字 reveal；第一帧必须完整可读。

## 视觉路线
1. 数字矛盾：下载 512 Mbps 与 Ping 180 ms 同时成立。
2. 两个维度：THROUGHPUT vs ROUND TRIP。
3. 游戏内网络统计：先看真正到游戏服务器的 Ping。
4. 稳定低延迟 vs 延迟大幅波动；只点到 jitter / packet loss。

## 主动不做
- 不画无意义赛博网络粒子。
- 不把 packet 做成发光球。
- 不用复杂拓扑。
- 不解释 Wi-Fi、Bufferbloat、路由和加速器。

## 数据目标
- 2s 跳出 <35%
- 5s 播放率 >30%
- 平均播放 >6s
- 正文目标约 20–23s，完整成片约 25–28s
