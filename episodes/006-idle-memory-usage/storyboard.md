# EP006 Storyboard

## Shot 1 — Hook：16GB 怎么已经用了 7.4GB？

- 时间：T0 → T1
- 主信息：刚开机的任务管理器已经显示内存占用接近一半。
- 稳定元素：Windows 任务管理器风格内存卡；`16.0 GB` 总内存；`7.4 GB 已使用`。
- 主运动对象：占用条从 0 推进到约 46%。
- 因果关系：先建立观众真实见过的问题，不先解释。
- 结束状态：`什么都没开，内存去哪了？`

## Shot 2 — “已使用”不只等于应用列表

- 时间：T1 → T2
- 主信息：整机已使用还包含系统、内核/驱动、后台服务与进程工作集。
- 稳定元素：16GB 物理内存条；四类可识别实体卡片。
- 主运动对象：四类占用依次进入同一内存条。
- 因果关系：解释为什么“进程列表简单相加”与总占用可能对不上。
- 结束状态：`整机已使用 ≠ 只看应用列表`

## Shot 3 — 缓存 / 待机内存

- 时间：T2 → T3
- 主信息：Windows 会把最近使用的数据留在待机缓存里，减少下次读取成本。
- 稳定元素：文件卡 → Standby Cache；任务管理器风格 `缓存` 与 `可用` 指标。
- 主运动对象：文件数据进入待机缓存。
- 因果关系：缓存不是“神秘消失的内存”，而是系统主动利用 RAM。
- 结束状态：`Standby ⊂ Available`

## Shot 4 — 核心反转：需要时可以让位

- 时间：T3 → T4
- 主信息：待机内存属于可用内存，程序真正需要时可以重新分配。
- 稳定元素：左侧待机缓存，右侧新应用。
- 主运动对象：一部分缓存块转移为应用实际占用。
- 因果关系：应用提出内存需求 → standby 让位 → 应用获得空间。
- 结束状态：`缓存占着 ≠ 被锁死`

## Shot 5 — 真正应该看什么

- 时间：T4 → T5（T5 为 canonical outro 起点）
- 主信息：别只盯开机占用率；判断是否真的缺内存，要看可用内存和真实性能表现。
- 稳定元素：三项检查卡：`可用长期很低`、`常用软件后接近满载`、`明显卡顿`。
- 主运动对象：从单一“已使用 46%”切换到三项判断。
- 因果关系：把抽象机制重新接回用户判断。
- 结束状态：`别只盯“已使用”`

## Outro

- T5 开始：正文 ownership 清空；canonical 横版 outro 同帧开始。
- 品牌句：`这里是 7BYTE，把计算机讲简单一点。`
