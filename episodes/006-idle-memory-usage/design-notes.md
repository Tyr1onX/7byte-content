# EP006 Design Notes

## 数据驱动的本期目标

EP005 跑一天多后的观测：播放约 `1375`、点赞 `23`、收藏 `6`、完播率 `4.35%`、2s 跳出 `29.08%`、5s 播放率 `37.89%`、平均播放 `16s / 29.41%`。

结论：前段留人相较往期已有改善，但 50s+ 视频在后半段明显承压；同时连续两期存储单位题材不继续叠加。

EP006 只做两项明确变化：

1. 选题换成更广泛的 Windows 日常痛点。
2. 把最终时长压到约 `40s`，核心反转提前到正文约 20–24 秒前。

发布节奏实验独立记录：下一次发布采用“中间空两天”的节奏，不因此改品牌或视觉系统。

## 主视觉语言

本期不做“纯文字教程”。至少保留三个可识别实体：

1. Windows Task Manager 风格内存概览卡。
2. 内核/驱动、后台服务、应用等系统内存来源卡。
3. Standby Cache 与新应用之间的重新分配关系。

核心视觉记忆：

`16GB → 7.4GB 已使用` → `已使用不只等于应用` → `Standby 属于 Available` → `需要时让位` → `真正看可用与卡顿`

## 画面文字职责

允许：

- `16.0 GB`
- `7.4 GB 已使用`
- `46%`
- `内核 / 驱动`
- `后台服务`
- `应用工作集`
- `Standby Cache`
- `Available / 可用`
- `缓存占着 ≠ 被锁死`
- `别只盯“已使用”`

不把完整口播句复制进画面。

## 技术准确性边界

- 不说“Windows 会故意把所有空闲内存占满”。
- 明确区分 `In Use` 与 `Available`；standby 属于 available，不把 standby 错说成全部计入“已使用”。
- 不把所有看不见的内存都归因于缓存或 Memory Compression。
- 不制造“超过 50% 就正常 / 超过 80% 就异常”之类固定阈值。
- 判断是否需要排查，以可用内存、持续内存压力和实际卡顿共同判断。

## Motion 语气

- 普通位移/显隐约 `0.6–1.0s`。
- 一次只突出一个主运动对象。
- Shot 2 的内存来源以稳定分段条和实体卡为主，不做满屏飞块。
- Shot 4 只做一次清晰的“standby 让位给 app”因果动画。
- 不使用蓝紫渐变、粒子、glitch、快速 zoom。
