音频：`7byte口播.m4a`  
实测时长：约 **99.26 秒**。  
当前时间点根据这次实录的语速、停顿和既定口播文本做第一轮对齐；后续如果重新录音，只需要替换这一份 cue 时间，不需要重做视觉。

## 字幕规则
- 固定在下方安全区，不跟随浏览器、DNS、Server 或 packet 移动。
- 最大宽度约 `880px`，最多两行。
- 字号约 `36px`，暖白字，深色轻量底板。
- 字幕忠实跟随实际口播，但按手机阅读节奏拆成完整语义单元。
- 不做逐字卡拉 OK、不做高亮跳字。
- 英文术语保留原写法：`baidu.com`、`IP`、`DNS`、`HTTPS`、`HTTP`、`GET /`、`HTML`、`CSS`、`JavaScript`。
- 片尾已经直接显示 `7BYTE / 把计算机讲简单一点。`，最后两句可以由片尾本身承担，不额外堆一层重复字幕。

## 实录 cue

### Hook · 00:00–00:09.9
- `00:00.0–00:01.0` 你有没有想过？
- `00:01.0–00:04.7` 当你在浏览器里输入 `baidu.com`，然后按下回车。
- `00:04.7–00:06.8` 看起来只是打开了一个网页。
- `00:06.8–00:09.9` 但背后其实已经跑完了一整套互联网流程。

### DNS · 00:09.9–00:33.2
- `00:09.9–00:12.6` 第一步，浏览器得先知道：百度到底在哪。
- `00:12.6–00:18.7` 网络通信真正要找的，不是 `baidu.com` 这个名字。
- `00:18.7–00:20.9` 而是服务器对应的 IP 地址。
- `00:20.9–00:23.1` 所以浏览器会先去问 DNS。
- `00:23.1–00:25.8` 这个域名，对应哪个 IP？
- `00:25.8–00:28.8` DNS 把地址返回来以后。
- `00:28.8–00:33.2` 浏览器才知道接下来该去找哪台服务器。

### 连接 + HTTPS · 00:33.2–00:44.7
- `00:33.2–00:36.0` 找到服务器以后，接下来就要建立连接。
- `00:36.0–00:38.8` 如果访问的是 HTTPS。
- `00:38.8–00:41.0` 还会先建立一条加密通道。
- `00:41.0–00:44.7` 后面的数据就会通过这条通道来传输。

### HTTP · 00:44.7–00:55.9
- `00:44.7–00:45.8` 连接准备好以后。
- `00:45.8–00:50.8` 浏览器才会真正发送 HTTP 请求。
- `00:50.8–00:51.7` 比如 `GET /`。
- `00:51.7–00:54.4` 你可以简单理解成一句话。
- `00:54.4–00:55.9` “把首页给我。”

### 资源返回 · 00:55.9–00:72.7
- `00:55.9–00:58.1` 服务器收到请求以后。
- `00:58.1–01:01.9` 就会把网页需要的东西陆续发回来。
- `01:01.9–01:05.8` 比如 HTML 负责页面结构。
- `01:05.8–01:07.4` CSS 负责样式。
- `01:07.4–01:09.4` JavaScript 负责交互。
- `01:09.4–01:12.7` 图片这些资源也会一起加载。

### 浏览器渲染 · 01:12.7–01:22.7
- `01:12.7–01:15.3` 浏览器一边接收这些内容。
- `01:15.3–01:19.7` 一边解析、排版，再把它们绘制到屏幕上。
- `01:19.7–01:22.7` 最后，你才真正看到了这个网页。

### 总结 + 片尾 · 01:22.7–01:39.3
- `01:22.7–01:25.8` 所以你以为自己只是按了一次回车。
- `01:25.8–01:33.9` 但实际上背后已经完成了找地址、建立连接、加密、请求、传输和渲染这一整套流程。
- `01:33.9–01:35.7` 这里是 7BYTE。
- `01:35.7–01:37.8` 把计算机讲简单一点。
- `01:37.8–01:39.3` 片尾自然停留。

## 动画同步原则
- 视觉动作落在关键词附近，而不是等整句话说完才动。
- DNS Query 在“去问 DNS”附近出发；DNS Answer 在“地址返回来”附近返回。
- Server 在“找到服务器以后”出现；HTTPS 状态在“加密通道”附近完成。
- `GET /` packet 在说到 `GET /` 前后进入主要运动。
- HTML / CSS / JavaScript / IMG 分别跟对应口播出现，并让浏览器内部发生可见变化。
- “解析、排版、绘制”期间让完成后的浏览器回到中心并稳定停留。
- 总结阶段减少新动作，以总结卡和 7BYTE 片尾为主。
