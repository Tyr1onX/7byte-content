# Storyboard v3 · 60 秒节奏版

目标时长：约 58～62 秒。视觉方案沿用已经通过第一轮验收的 V3；这一版只重新设计节奏。

核心原则：**不要把所有动画机械地放慢。** 元件真正移动时仍保持利落，主要通过“状态停留”和“口播对应的阅读时间”把整条片拉到约一分钟。观众应该先看见动作，再有时间理解动作的结果。

## 00:00–00:07 — 输入 baidu.com
- 浏览器作为唯一视觉主角。
- 先留约 1 秒让观众看清浏览器。
- `baidu.com` 逐字输入，不要像打字机特效一样过快。
- Enter 后至少停留 1 秒，再进入 DNS。
- 这一段对应口播 Hook，不能在口播还没说完时就切走。

## 00:07–00:20 — DNS 找地址
- 浏览器移动到上方后停稳，再出现 DNS。
- `DNS QUERY` 单程约 1.2～1.4 秒。
- 查询到达 DNS 后停约 0.7～1.0 秒。
- `DNS ANSWER` 返回约 1.2～1.4 秒。
- `baidu.com → IP 地址` 结果至少保留 2 秒。
- 整段的重点不是 packet 飞行，而是让观众理解“域名先变成 IP”。

## 00:20–00:31 — 建立连接 + HTTPS
- DNS 淡出后不要立刻连续切两个状态；先让 Server 稳定出现。
- `连接已建立` 保留约 2 秒。
- 再切换到 `HTTPS · 加密通道`，保留约 3 秒。
- 运动本身仍控制在约 0.8～1.0 秒，时间主要留给状态理解和口播。

## 00:31–00:38 — HTTP 请求
- 主字幕进入后先给观众约 1 秒阅读。
- `GET /` packet 向服务器移动约 1.2～1.4 秒。
- 到达服务器以后不要马上进入资源返回，保留约 1.5～2 秒，配合“把这个页面给我”。

## 00:38–00:51 — 资源陆续返回
依次返回：

1. `HTML / 页面结构`
2. `CSS / 布局 + 样式`
3. `JS / 交互逻辑`
4. `IMG / 图片资源`

每个资源使用同一节奏模板：
- packet 返回约 1.0～1.2 秒；
- 到达后浏览器发生对应变化约 0.4～0.6 秒；
- 新状态额外停约 0.7～1.0 秒，让观众看清变化。

不要四个资源无缝连发。资源之间需要呼吸感，与口播中的 HTML / CSS / JavaScript / 图片逐项对应。

## 00:51–00:56 — 浏览器完成渲染
- Server 和连接淡出。
- 同一个浏览器平稳回到中央并恢复完整尺寸。
- 完整页面至少停 2.5 秒。
- 这一段对应“解析、排版和绘制 / 最后你才看到了网页”。

## 00:56–01:00 — 总结 + 片尾
- 总结只保留：`找地址 → 建连接 → 加密 → 请求 → 传输 → 渲染`。
- 总结约 2～2.5 秒。
- `7BYTE / 把计算机讲简单一点。` 约 2 秒。
- 不额外增加复杂转场。

## 最终音频锁定
当前时间点用于把无声预览先调整到正常的一分钟观看节奏。真正录好口播后，以音频波形为最终基准微调：每个视觉状态切换尽量落在对应关键词附近，而不是强行保持固定秒数。
