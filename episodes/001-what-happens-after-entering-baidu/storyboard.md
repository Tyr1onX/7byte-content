# Storyboard v2

目标时长：约 50～57 秒。核心不是“展示网络拓扑”，而是让观众从一次真实浏览器操作，自然走进它背后的机制，再回到网页结果。

## 00:00–00:06 — 浏览器入口
- 程序化复现一个干净的浏览器窗口。
- 地址栏逐字输入 `baidu.com`，短暂停顿，出现 Enter 提示。
- 不先展示流程图，不堆术语。
- 开场标题只做一次：`输入 baidu.com 后发生了什么？`

## 00:06–00:17 — DNS 找地址
- 浏览器缩到左侧后保持位置稳定。
- DNS 节点出现在右上。
- 唯一主运动对象是 packet：
  1. `DNS QUERY / baidu.com ?` 从浏览器走向 DNS；
  2. 停顿；
  3. `DNS ANSWER / IP address` 返回。
- 结果卡停留：`baidu.com → IP 地址`。
- DNS 完成任务后只降低存在感，不突然换一套布局。

## 00:17–00:27 — 连接 + HTTPS
- 服务器固定出现在右下。
- 一条连接线从浏览器向服务器画出。
- 先显示 `连接已经建立`。
- 再出现一个克制的 `LOCK` 状态，说明 HTTPS 建立加密通道。
- 不在这一期展开 TCP 三次握手，也不让观众误以为所有浏览器访问都只对应一种传输路径。

## 00:27–00:34 — HTTP 请求
- 沿已经存在的连接发送实体 packet：`GET /`。
- packet 到服务器后停一下。
- 显示 `服务器收到请求`。
- 不使用发光球、流星或粒子代表数据。

## 00:34–00:47 — 资源返回并改变页面
服务器按节奏依次返回：

1. `HTML / structure` → 浏览器出现页面结构；
2. `CSS / styles` → 搜索框和样式出现；
3. `JS / behavior` → 显示交互 ready；
4. `IMG / assets` → 页面资源进一步完整。

每次只有一个资源 packet 在移动，而且 packet 到达后，浏览器内部必须发生对应的可见变化。重点是“因果关系”，而不是四张卡片飞来飞去。

## 00:47–00:52 — 回到浏览器结果
- DNS、服务器、连接逐渐淡出。
- 同一个浏览器从左侧恢复到画面中心并放大。
- 显示 `页面渲染完成`。
- 让观众意识到：刚才所有抽象步骤，就是最开始那个浏览器页面背后发生的事。

## 00:52–00:57 — 总结 + 片尾
先快速总结：

`找地址 → 建连接 → 加密 → 请求 → 传输 → 渲染`
