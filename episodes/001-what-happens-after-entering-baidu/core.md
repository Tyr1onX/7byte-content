# Core — 输入 `baidu.com` 后发生了什么？

> 平台无关的内容母稿。视频、小红书、公众号都从这里取知识，不把各平台包装反写回来。

## 核心问题

在浏览器地址栏输入 `baidu.com` 并回车，到页面真正出现在屏幕上之间，电脑大体经历了什么？

## 观众最终只需要记住

一个简化但正确的主链路：

`域名 → 找到服务器地址 → 建立安全通信 → 发出网页请求 → 收到页面资源 → 浏览器解析与渲染`

用户只看到一次回车，背后其实有一整条网络与浏览器协作链路。

## 事实链路

1. **确定目标地址**：浏览器需要把 `baidu.com` 这样的域名解析到可通信的网络地址。实际过程中可能命中浏览器、系统或网络侧缓存；需要查询时通常会经过 DNS 解析。
2. **建立通信**：获得可用地址后，客户端与目标服务建立传输连接。实际协议可能随浏览器、服务端和网络环境而不同；本期只讲“先建立可传输数据的连接”这一层。
3. **建立安全层**：访问 HTTPS 网站时，需要建立加密且能验证服务器身份的安全通信。本期只解释其目的，不展开证书链、密钥交换和 TLS 版本细节。
4. **发送网页请求**：浏览器通过 HTTP 语义请求需要的资源。用 `GET /` 可以帮助初学者理解“请求首页”这个动作，但真实请求头、重定向和协商过程可能更复杂。
5. **返回资源**：服务器返回 HTML，并可能触发 CSS、JavaScript、图片、字体等后续资源请求。
6. **解析与渲染**：浏览器解析文档、样式和脚本，进行布局、绘制并执行必要的交互逻辑，页面逐步出现在屏幕上。

## 关键概念

- **域名**：便于人记忆的网站名称，不等于最终通信时直接使用的网络地址。
- **DNS**：把域名解析到网络地址的系统；缓存存在时不一定每次都重新查询。
- **IP 地址**：网络寻址的重要标识之一。
- **HTTPS / TLS**：为 HTTP 通信提供加密、完整性保护和服务器身份验证等安全能力。
- **HTTP**：浏览器和 Web 服务交换请求与响应所使用的应用层协议语义。
- **HTML / CSS / JavaScript**：分别主要承担页面结构、样式与行为/交互。
- **渲染**：浏览器把收到的资源处理成最终可见页面的过程。

## 本期边界

为了保持主线清楚，本期不展开：

- DNS 缓存层级、递归/迭代查询、DoH/DoT
- CDN、负载均衡、Anycast 等服务器侧路径
- TCP 与 QUIC / HTTP/2 / HTTP/3 的协议差异
- TLS 握手和证书链细节
- 浏览器缓存、Service Worker、预连接、预加载
- DOM / CSSOM / Render Tree 的完整渲染细节
- 重定向、Cookie、请求头与内容协商

这些都可以拆成后续独立 episode。

## 可复用表达

- “你以为只是按了一次回车，电脑实际完成了找地址、建连接、加密、请求、传输和渲染。”
- “域名更像你记住的名字，网络还需要知道真正该去哪里。”
- “`GET /` 可以先理解成：把首页给我。”

## 表达注意

- 不说“每次输入网址都一定会先请求 DNS”，因为可能命中缓存。
- 不把“建立连接”强行限定为 TCP；现代 Web 可能使用 QUIC / HTTP/3。
- 不把 HTML、CSS、JS 描述成服务器一次性必然全部返回；它们可能通过后续多个请求获取。
- 这是面向普通用户的主链路解释，不追求在一期里覆盖完整协议栈。
