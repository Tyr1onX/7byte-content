你看到的是“网页打开了”。
电脑背后跑的是一整条 网络 + 浏览器 协作链路。

先有全局，再看细节02 / 08
01 / 找地址

baidu.com
不是服务器地址

域名更像人方便记住的“名字”。
网络还需要知道真正该去哪里。

baidu.com
↓
缓存 / DNS
↓
可通信的网络地址
别记错：不是每次输入网址都一定重新请求 DNS。缓存命中时，可以直接拿到结果。
DNS：把“名字”翻译成“去哪里”03 / 08
02 / 建立连接

找到服务器后
第一件事不是拿网页

先连上。

浏览器要先和目标服务建立一条能传数据的连接。

先把路打通，
后面的数据才有地方走。
准确一点：这里不把“连接”强行写成 TCP。现代 Web 可能使用不同的传输协议。
先理解动作，再拆协议细节04 / 08
03 / HTTPS

HTTPS 不只是
“地址栏多了个锁”

访问 HTTPS 网站时，还要建立安全通信。

加密

别人不容易直接看懂传输中的内容。

完整性

数据在途中不应该被悄悄篡改。

验证身份

确认你连接的服务器是谁。

HTTP 数据 → 安全层里传输
HTTPS = HTTP + 安全能力（简化理解）05 / 08
04 / HTTP 请求

现在，浏览器才真正“开口”

GET /
“把首页给我。”

真实请求还会带上请求头、协商信息等内容。
这一页先抓住最核心的动作：浏览器向服务器请求资源。

HTTP 负责“怎么请求、怎么回应”06 / 08
05 / 返回资源

网页不是一个文件
直接飞回来

HTML页面结构
CSS页面样式
JS行为与交互
图片 / 字体继续补齐页面内容
关键：这些资源可能通过多个后续请求逐步加载，不是服务器一次性把“完整网页文件”全部塞回来。
浏览器会继续请求它缺的资源07 / 08
06 / 渲染

最后，资源才变成
你真正看到的网页

浏览器继续解析、排版、绘制，并执行需要的脚本。

找地址 → 建连接
↓
安全通信 → HTTP 请求
↓
收资源 → 浏览器渲染

你以为只是按了一次回车，背后其实已经跑完了整条链路。
