# EP008 Design Notes

## 数据驱动目标

EP007 在约 29 秒完整时长下，早期数据出现：平均播放仍约 8 秒，但平均播放占比明显高于 40 秒版本，5 秒播放率和完播结构也改善。本期继续保持短正文，不为了凑时长加入文件系统细枝末节。

目标：核心答案在约 6 秒内建立；TRIM 边界在 15–22 秒进入；正文控制在约 25–30 秒，再接 canonical outro。

## 发布节奏

- 抖音默认继续约 `48h` 一期。
- 制作可以提前完成，实际发布仍按平台节奏执行。

## 画幅与空间契约

- `1920×1080 / 16:9 / 60fps`
- 主视觉带约 `y=-350..280`
- 字幕保留带约 `y=320..500`
- 关系型解释继续使用横版成熟母版。
- `project.meta == capture == final output`
- Scene 不绘制 canonical 左上角 header；最终 composite 唯一 overlay。

## 品牌层

完全复用横版品牌锁：`#0F100E` 背景、固定中央水印、canonical header、canonical horizontal outro、Yunyang `-5%`，品牌句与 outro 同帧起步。

## 主视觉语言

1. 文件卡 / 文件系统索引：表示“用户看到的文件”。
2. 一组稳定的数据块：表示“底层内容”。
3. `占用 → 可用` 状态切换：表达删除真正改变的核心状态。
4. 扫描框：表达恢复软件找残留，不做赛博扫描特效。
5. HDD / SSD 双卡对比：SSD 上只出现 `TRIM → 可回收`，避免过度承诺物理擦除时机。

## 画面文字职责

允许：`文件记录`、`数据块`、`已占用`、`可再次使用`、`仍有旧内容`、`HDD`、`SSD`、`TRIM`、`可回收`、`删除 ≠ 安全擦除`、`误删 → 停止写入`。

不把完整口播复制进画面。

## Motion 语气

- 主要状态变化 `0.6–1.0s`。
- 一次只有一个主运动对象。
- 块状态用 fill / badge 改变，不用发光粒子。
- 不做复杂 matched geometry；每个 shot 自己拥有对象。

## 字幕

- 使用 7BYTE Auto Subtitle Skill。
- Hook 第一 cue 由大标题完整承担，T0→T1 抑制普通字幕。
- 品牌句从 T5 起抑制普通字幕。
- `SSD / TRIM / HDD` 不拆。
