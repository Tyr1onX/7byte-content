# EP005 Storyboard

## Shot 1 — 为什么不统一单位？

**时间：** `T0 → T1`

- 主信息：同一个容量问题为什么会出现两种“GB”算法？
- 稳定元素：左侧 `500 GB` 硬盘标签、右侧 Windows `465 GB`。
- 主运动：两块卡依次进入，中央问题出现。
- 结束状态：观众先建立冲突，不提前塞入 GiB 定义。

## Shot 2 — 标准其实已经分开

**时间：** `T1 → T2`

- 主信息：`GB = 10^9 B`，`GiB = 2^30 B`。
- 稳定元素：左右两把“尺子”，中间同一份 Bytes。
- 主运动：同一份数据分别被十进制与二进制标尺框住。
- 因果：不是数据变了，而是单位定义不同。
- 结束状态：观众第一次明确认识 `GiB`。

## Shot 3 — 为什么当年会混用？

**时间：** `T2 → T3`

- 主信息：早期计算机天然围绕 2 的幂，`1024 ≈ 1000`，于是借用了 kilo / mega / giga 的名字。
- 稳定元素：老式计算机 / 内存实体、`1024` 计数块、旧 `KB / MB / GB` 标签。
- 主运动：`1024` 计数块与 `1000` 标尺靠近，旧标签盖上。
- 结束状态：让“历史习惯”成为可理解的原因，不说成谁故意造错单位。

## Shot 4 — 1998：标准给出新名字

**时间：** `T3 → T4`

- 主信息：IEC 在 1998 年正式引入 `KiB / MiB / GiB`。
- 稳定元素：标准文档卡；两列单位。
- 主运动：原本混在一起的 `KB / MB / GB` 分成两条清晰轨道：十进制与二进制。
- 重点停留：`GB ↔ GiB` 至少保留 1 秒。
- 这是本期 20 秒附近的第二次认知推进。

## Shot 5 — 为什么今天还会看到 GB？

**时间：** `T4 → T5`

- 主信息：标准变了，但软件与用户习惯没有同步切换。
- 稳定元素：程序化 Windows Explorer 磁盘卡、时间轴 `1998 → today`。
- 主运动：标准标签 `GiB` 出现后，Explorer UI 仍显示 `GB`。
- 结束状态：把“Windows 算错”改成更准确的“旧显示标签仍被沿用”。

## Shot 6 — 最终模型

**时间：** `T5 → T6`

- 主信息：没完全统一的是显示习惯，不是单位定义。
- 稳定元素：
  - `GB = 10^9 B`
  - `GiB = 2^30 B`
  - `500 GB ≈ 465.7 GiB`
- 主运动：500GB 从十进制尺子映射到 465.7GiB，然后停住。
- 结束状态：正文干净停在“两把尺子”结论，`T6` 同帧切 canonical outro。
