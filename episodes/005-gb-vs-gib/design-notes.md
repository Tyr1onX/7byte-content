# EP005 Design Notes

## 本期视觉目标

承接 EP004 的讨论，但不能做成“EP004 公式卡加长版”。

核心视觉记忆：

1. `为什么不统一单位？`
2. `GB = 10^9 B` vs `GiB = 2^30 B`
3. `1998 IEC` 把二进制单位正式命名为 `KiB / MiB / GiB`
4. **定义统一了，显示习惯没完全统一**

## 唯一实验变量：约 20 秒的第二次认知推进

EP004 已验证：

- 2 秒跳出约 `33.15%`
- 5 秒完播约 `36.21%`
- 平均播放约 `12.62s / 21.96%`
- 完播率约 `5.62%`

开头不再大改。本期主要针对留存曲线约 20 秒的第二个低谷：

- 前段先回答“标准其实已经统一”。
- 中段解释历史混用原因。
- **约 20 秒明确打出 `1998 IEC → KiB / MiB / GiB`**，形成新信息，而不是继续平铺历史。

## 可识别实体

至少存在三个真实语义实体，不退化成纯文字标签：

1. 硬盘容量标签 / 产品卡
2. 早期计算机 / 内存实体，用来解释为什么 1024 历史上自然
3. Windows Explorer 风格磁盘容量 UI，用来表现“计算口径与显示标签”的区别

标准阶段允许使用文档卡，但它必须是“标准文件 / 规范”的视觉实体，而不是又一张无意义公式卡。

完整解释仍交给旁白 + 字幕。

## 技术准确性

- `GB` 严格按十进制，`GiB` 严格按二进制。
- `1024^3 B` 不直接写成“真正的 GB”；应写 `GiB`。
- 早期行业曾用 KB / MB / GB 表示二进制倍数，这是历史习惯，不等于今天标准定义。
- IEC 在 1998 年批准二进制前缀。
- Windows Explorer 长期仍使用传统 KB / MB / GB 标签展示 1024-based 结果。
- 不用“Windows 算错”“厂商一定虚标”这种简单结论。

## Motion 语气

- 普通位移约 `0.8–1.2s`，继续保持 EP004 的可消化节奏。
- `GiB` 第一次出现时必须停住，不一闪而过。
- 1998 标准镜头用“分轨”表达消除歧义，而不是满屏飞字。
- 不做蓝紫赛博、发光粒子、快速 zoom。
- shot 之间 semantic cut 为主；不同抽象层级不强求复杂 proxy handoff。
