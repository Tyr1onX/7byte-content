# EP005 Idea — 同样是 1GB，为什么硬盘厂商和 Windows 算得不一样？

## 本期只回答一个问题

既然 `500GB → 465GB` 的根源是十进制与二进制换算不同，为什么行业不直接把单位统一？

核心答案不是“单位一直没有标准”，而是：

> **标准其实早就把两套单位分开了；真正没有完全统一的是软件与用户的显示习惯。**

## 观众看完只需要记住

- `1 GB = 10^9 B`
- `1 GiB = 2^30 B`
- IEC 在 1998 年引入 `KiB / MiB / GiB` 等二进制前缀，目的就是消除 `KB / MB / GB` 被两种算法复用的歧义。
- Windows Explorer 长期仍沿用 `KB / MB / GB` 标签显示 1024-based 的结果，所以今天仍会看到“定义已经分开，显示习惯却没完全跟上”的情况。

## 为什么现在做

EP004《500GB 硬盘，为什么电脑只显示 465GB？》的数据明显改善，并自然引出评论区问题：

- 为什么不能统一单位？
- GB 和 GiB 到底是什么关系？
- Windows 是不是一直写错单位？
- 厂商到底算不算虚标？

EP005 直接承接这个讨论，但不要求观众看过 EP004。

## 本期实验变量

**20 秒附近的第二次信息增量。**

EP004 的 2 秒跳出、5 秒完播已经稳定改善，但留存曲线约 20 秒仍出现第二个低谷。本期保持品牌、语速、字幕和整体节奏不变，只测试：

1. Hook：先抛“为什么不统一单位？”
2. 第一层答案：标准其实早就统一了。
3. 历史原因：1024 接近 1000，早期行业借用 KB / MB / GB。
4. **约 20 秒揭示 1998 IEC → KiB / MiB / GiB**，形成第二次明确认知推进。
5. 回到今天：定义统一了，但软件显示习惯没完全统一。

## 技术口径

- SI / 国际标准中的 `GB` 是十进制：`1 GB = 1,000,000,000 B`。
- IEC 二进制前缀中：`1 GiB = 1,073,741,824 B = 2^30 B`。
- 不说“GB 本来就等于 1024^3 B”。那是历史习惯用法，不是今天标准化后的严格定义。
- 不把 Windows 的历史标签简单说成“系统算错”；应说它用 1024-based 计算，但长期仍显示旧的 KB / MB / GB 标签。
- 不把厂商十进制 GB 直接定性成“虚标”；本期解释单位定义与显示习惯。
