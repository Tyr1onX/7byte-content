# EP004 Design Notes

## 本期视觉目标

延续 EP003 已经验证有效的“数字冲突 + 可识别 UI”，但不复制 `1000 Mbps ÷ 8` 的视觉模板。

核心记忆：

1. `500GB → 465GB`
2. `厂商：1000` vs `Windows：1024`
3. `465.7` 更接近二进制的 `GiB`

## 唯一实验变量：5–20 秒中段留存

EP003 的 Hook 已明显改善，但 5 秒后留存仍落到同类之下。本期不再折腾品牌、配色、片尾或发布时间视觉，而是在 Hook 后连续安排新的认知推进。

- 5–约12秒：先回答“厂家为什么敢写 500GB”
- 约12–25秒：立即制造第二个问题“为什么 Windows 用 1024”
- 该段后半再揭示 `GiB`，不让解释进入平铺状态

## 画幅与空间契约

- `1920×1080 / 16:9 / 60fps`
- 主视觉约 `y=-350..280`
- 字幕保留带约 `y=320..500`
- `project.meta == capture == final`

## 横版品牌层

完全复用 `shared/brand/horizontal-video-brand-lock.md`：

- Background / Surface / Border / Text / Accent 全部使用 `HORIZONTAL_BRAND`
- 中央 `7BYTE` 水印固定，不动画、不改位置
- scene 内不画左上角品牌头
- 最终 composite 只叠 `/7BYTE/brand/header-horizontal.png`
- 横版结尾只 append `/7BYTE/brand/outro-horizontal-canonical.mp4`
- 固定品牌句与 outro 同帧开始

## 可识别 UI

本期禁止退化成五张公式卡。

必须至少存在两个可识别实体：

1. **实体硬盘/SSD 包装卡**：观众一眼知道“这是买来的 500GB 硬盘”
2. **Windows 磁盘容量 UI**：进度条 / drive 状态 / `465 GB`，而不是只有一块写字的 Rect

`厂商 1000` 与 `Windows 1024` 是两把“尺子”的视觉关系，不做成无意义装饰线。

## 画面文字职责

画面只写：数字、单位、尺子、实体名、状态和简短公式。

旁白 + 字幕负责完整句子。禁止把“其实硬盘没有缩水”同时做成 headline、说明句和字幕三遍重复。

## 技术准确性

- 厂商十进制容量：`1 GB = 10^9 Bytes`
- `500,000,000,000 / 1024^3 ≈ 465.66`
- 二进制单位严格称 `GiB`
- Windows 历史上常将这种二进制换算结果以 `GB` 标签展示，因此视频必须说“更接近 GiB / 常显示成 GB”，不能简单声称行业里 `1GB=1024³ Bytes` 是唯一标准。
- 格式化 / 系统分区只作为可能的额外少量占用，不把 500→465 的主体差异错误归因于格式化。

## Motion 语气

- 干净 semantic cut 优先
- 不 fade-to-empty
- 一次只有一个主关系动作
- 两把尺子的切换要表现“同一堆 Bytes 被不同规则分组”，不是两个无关页面
- `GiB` badge 延迟到中段后半揭示，作为留存信息增量

## 发布实验

EP003 在 18:18 发布后获得明显更大的推荐扩量，但样本仍少。EP004 暂不把发布时间作为新的实验变量；如发布时条件允许，继续保持 `18:00–18:30`，把内容结构作为主要变量。
