# EP004 Storyboard

> 时间以最终 TTS timing 为准。这里描述语义 phase，不把估算秒数当 source of truth。

## Shot 1 — 500GB → 465GB

旁白：买了一块 500GB 硬盘……其实硬盘没缩水。

画面唯一主信息：

- 左：可识别 SSD / 硬盘包装 UI，巨大 `500 GB`
- 右：Windows 风格磁盘容量卡，巨大 `465 GB`
- 中下：`35GB 去哪了？`

第一帧就建立冲突。Hook 自身已经完整表达问题，因此这一 phase 普通字幕抑制。

## Shot 2 — 厂商的尺子：1000

旁白：厂家标容量时……500GB 就是 5000 亿字节。

画面：

- 一个大的“字节池”对象表示 `500,000,000,000 Bytes`
- 左侧出现一把明确标为 `厂商` 的尺子
- 尺子刻度连续强调 `1000 → 1000 → 1000`
- 得到稳定结果 `500 GB`

避免一上来堆公式；先让观众看到“厂商用的是 1000 这把尺子”。

## Shot 3 — Windows 的尺子：1024

旁白：但 Windows……更接近 GiB。

这是本期专门优化中段留存的关键 shot。

画面：

- 同一个字节池保持语义 owner
- 第二把尺子切换为 `Windows / 1024`
- `1024 B → 1 KB → 1024 KB → 1 MB → 1024 MB → 1` 的关系分层建立
- 约在该 shot 后半段才揭示一个 accent badge：`更准确：GiB`

不要在 Shot 2 就提前告诉观众 GiB，让中段有新的信息增量。

## Shot 4 — 5000 亿 ÷ 1024³ = 465.7

旁白：于是同样的 5000 亿字节……大约就是 465.7。

画面稳定公式：

`500,000,000,000 B  →  ÷ 1024³  →  465.7`

随后右侧结果自然接回 Windows 磁盘 UI。

## Shot 5 — 没少，只是尺子不同

旁白：格式化和系统分区……只是两边用的尺子不一样。

画面：

- 主体仍是 Windows 磁盘 UI `≈465 GB`
- 下方只增加两个低权重实体状态：`格式化`、`系统/恢复分区`
- 最终模型：`同一堆 Bytes · 两把不同的尺子`
- 结论稳定停留，不在片尾前再引入新知识
